02 / Enfoque

Entender.
Construir.
Mostrar evidencia.

  1. Partir de un problema real

    Un controlador faltante, una tarea cotidiana o un flujo confuso. Mantener la primera implementación fácil de inspeccionar.

  2. Hacer visibles los límites

    Detectar no es verificar. Las simulaciones no prueban hardware. Un prototipo no es un servicio de producción.

  3. Dejar un camino útil

    El código, los pasos de instalación, los casos de error y la documentación deben ayudar a quien continúe el trabajo.

03 / Notas

Field notes

Detectar no es dar soporte.

Un identificador USB puede coincidir con el catálogo aunque falte el controlador, no aparezca una interfaz o falle el escaneo. Antena distingue esos estados.

¿Qué puedes verificar?

Revisa el detector, el diagnóstico y las pruebas simuladas del repositorio público. El README registra las observaciones de hardware y sus límites. Para verificar el comportamiento físico, usa un dispositivo compatible y comparte solo observaciones sin datos personales.
